# 配置应用指南

保存和重新加载 `config.yaml` 都在设置页现有 hint 中收束为一个结果。
“无需重启应用”不等于 HTTP 永不短断：应用进程保持运行，但监听地址变化会自动重启服务。

| 操作/变化 | 应用行为与反馈 |
| --- | --- |
| 保存 | 先持久化，再应用；异步完成前显示“配置保存成功，正在应用…”。 |
| 从文件重新加载 | 先 Config.init（可能已发布 MODE），再填表及 GUI 字段校验，全部完成才请求热应用；任一步失败显示失败。已发布但未确认应用的 MODE 代次保留待应用事实，后续同模式保存/重载可重试。 |
| 表单非法、读写/解析失败 | 显示失败，保留现有 modal；不能残留上次成功提示，不会静默接受坏配置。 |
| 普通 controls、log、IP 列表 | 后续操作/请求读取新值，不重启 HTTP；日志仍遵循现有配置策略。 |
| 语言/主题 | 实时应用；语言变化保留并重译本次结果。 |
| Brightness.MODE | 沿现有 generation 后台应用，先清旧软件效果；无关的成功保存不重置亮度。失败的待应用代次可重试，已应用代次不会重复清理。 |
| 运行中或启动中的 Config HOST/PORT 真正变化 | 先停止当前实例/启动尝试，旧 loop 关闭后启动最新保存的监听；无确认弹窗，快速保存合并最新目标。 |
| stopped 时 HOST/PORT 变化 | 只更新下次启动默认参数，绝不自动 start。 |
| 新监听失败 | 尽可能恢复之前实际运行的监听一次；说明新配置仍已保存，以及旧服务已恢复或两次均失败、服务停止。 |
| 手动 stop / quit | 自动 stopping 时现有电源按钮仍可点击，用来取消待重启目标；重复取消幂等，普通 stopping 仍禁用。quit 取消排队重启，之后不再自动 start。 |
| 用户再次编辑任一表单值 | 清旧 hint/tooltip，旧异步结果不得重新冒出；单纯 focus、程序填表、翻译不算用户编辑。 |

MODE 序号保持：0 硬件优先、GUI 遮罩回退，1 仅遮罩，2 实验性 Gamma；Gamma 异常退出
可能残留偏色，需要手动校准。

只有 **Config HOST/PORT 真正改变** 才请求自动重启，无关保存不会把正在运行的手动监听
替换掉。主面板 detected/custom 地址选择、自定义 IP 和独立编辑的端口会保留；如果面板
端口仍等于旧 Config 端口，则跟随新默认端口。Config HOST/PORT 确实改变时，运行中的
服务改用新 Config bind，即使主面板仍有尚未提交的 custom 选择；原 dirty 提示仍说明这些
未应用的面板参数。

自动重启存在短暂断开。host/port 改变后旧 URL 可能失效，请查看实际监听日志和更新的 QR。
GUI Config 支持 `127.0.0.1`、`localhost`（仅本机客户端）及 `0.0.0.0`；通配地址 QR
仍按既有逻辑显示检测到的 LAN IP。

不会在绑定前报成功：worker 观察 Hypercorn serve 任务使用的已 await
`asyncio.create_server` 结果，解析期望 IPv4/localhost bind，核对 serving socket 的
family、地址及端口。`0.0.0.0` 必须匹配通配 socket，不能仅匹配同端口其他地址。
此 GUI 确认路径不支持 port 0、IPv6 或 Unix listener，并检查启动任务没有立即退出。Quart 的
`before_serving` 本身不是监听确认。旧 loop 关闭后才发 stopped 快照，新 start 排队进入
Qt worker，自动应用不阻塞 GUI 等待服务线程。监听确认 ready 后，该次监听应用结束；
后续健康故障只更新面板状态与日志，不改写已完成或更新保存/重载的 hint。仍在进行的自动
重启会向合并后的最新保存报告。ready 不是永久健康保证，fake asyncio 测试也不能证明
真实 Hypercorn/Windows 集成已通过。

同次保存的亮度、服务应用要一起等待。平台不支持、管理器不可用、restore 失败均给出失败，
不再声称“下次请求会成功”。需要重启应用的提示不保证驱动或 Gamma 校准问题能靠重启解决；
端口占用、地址不存在单独失败时显示服务应用失败，不声称重启能解决。组合失败的
tooltip/日志列出全部原因；即使同时绑定失败，也保留亮度或运行组件独立的“需要重启应用”
结论。loop close 失败明确要求重启，并禁止复用该 worker。旧服务恢复后，无关的重复保存
不反复重试坏 bind；修正原因后改变 HOST/PORT，
或明确手动 stop/start。

外部编辑文件后请使用“从文件重新加载”。GUI start 使用已加载配置，不在启动中途再次读
文件。没有新增跨进程锁；仍需真实 Qt/Windows、Hypercorn 和网络验收，永久阻塞的 native
IO 不能安全强杀。
